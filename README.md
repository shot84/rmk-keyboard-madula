## このブランチで変えたこと

| 変更 | 理由（配布版で起きたこと） | 確かめたこと |
| --- | --- | --- |
| BLE のマウスの報告を、まとめて・接続間隔ごと（15 ms 以上）に・8 ms 前までの動きで送る | LPPS を BLE で使うと、ポインタが遅れる・指を離した後も動き続ける。ホストが接続の回を飛ばすと、報告が送り口に溜まる | USB CDC の計測で、送り口の詰まりがほぼ消えた（1 秒のうち 300 ms 以上詰まる秒: Mac 45% → 0%。Windows は数十秒の計測と体感だけ）。動きの取りこぼしなし。代わりに遅れが約 8 ms 増える |
| Dial の購読（CCCD）を保存する | Windows で一度つなぎ直すと、Dial が反応しなくなる | つなぎ直した後も Dial が動く |
| Vial でキーマップを変えられるようにする | 配布版は GUI でキーマップを変えられない（`keyboard.toml` を変えてビルドし直す） | vial.rocks / Vial アプリで開け、変えたキーが再起動後も残る |
| 自分用のキーマップ（8 層・左のホイールを逆向き） | 作者の好み。使うときは Vial で変えるか、`keyboard.toml` を自分のものにする | — |
| 計測ログ（`[ble-tx]` `[lpps-tx]`） | 上の確認用。USB CDC にだけ出る | — |

`vial.json` は行列の位置から作った簡単な格子です（実物のキー配置の形ではありません）。

## 書き込むときの注意

- **Vial 入りの版と Vial なしの版（配布版など）を行き来すると、ペアリングと保存したキーマップが消えます**（Vial なし → 入りで確認。逆向きも同じはずですが未確認）。RMK の保存領域の並びが変わるためです。書き込んだ後、Windows / Mac でペアリングし直してください。
- Vial 入りの版では、キーマップは本体に保存されます。最初に書き込んだ後は、`keyboard.toml` を変えて焼き直しても反映されません。Vial で変えてください。
- Vial の解除（ロック）の仕組みは入れていないので、常に解除された状態です。つないだ PC からは、マクロも含めてキーマップを書き換えられます。
- 書き込み方は元の README と同じです（XIAO のリセットを 2 回 → UF2 をコピー）。Cornix 側は rc.4 のまま変えずに試しています。
- トラックボール（`madula-tb`）の版は、同じ変更でビルドしただけで、まだ実機で試していません。タッチパッド（`madula-iqs`）は Mac で使って確かめました（下の「タッチパッドで変えたこと」）。

## タッチパッド（`madula-iqs`）で変えたこと

| 変更 | 理由（配布版で起きたこと） | 確かめたこと |
| --- | --- | --- |
| 指の本数はトラックパッドのフラグだけで数え、0 本が 30 ms 続いてから「離した」とする | 3 本指を置いたまま、中クリックが連発することがある（指の数が 2 と 3 の間でちらつく） | Mac で連発は出なくなった（体感・ログでも再現なし） |
| 縦スクロールの向きを ZMK のドライバに合わせる | Mac（ナチュラルなスクロール）で上下が逆に感じる | Mac で自然な向き。Windows では逆に感じる（LPPS と同じ） |
| 2・3 本指タップの条件を ZMK と同じ 170 ms・移動 24 に（1 本指は配布版どおり 250 ms・移動 40） | 3 本指の中クリックが連発しやすい（上の行と同じ問題） | — |
| カーソルを等倍に（配布版は 1/2） | 遅い | Mac で体感 |
| 1 本指の動きを 3 フレーム（約 33 ms）遅らせて送り、指を離したら送っていない分を捨てる | 指を離すとき、最後に離れた側へカーソルが飛ぶ（チップが離れる直前の 2〜3 フレームで大きく動いたと報告する） | Mac で飛ばなくなった（体感）。代わりに約 33 ms 遅れる |
| チップの平滑化を強める（XY の動的フィルタの下限 beta 80 → 40） | ゆっくり細かく動かすとカーソルが揺れる | 小さい動きの向きが逆になる割合が減った（ログで数えた・サンプルは少ない）。揺れが残ると感じることもあった（表面のフィルムの影響は未確認） |
| 1 本指タップの後に触れるとドラッグ（タップドラッグ） | 配布版には無い | 単体テストだけ（実機では未確認） |
| 3 本指スワイプ（上・下・左・右で別々のキーを送る）。切り替えると 3 本指ドラッグ | 配布版には無い | Mac で 4 方向とも ⌃矢印が送られた（ログ）。使った感触は良い。Windows でもキーは届き、既定の Ctrl+矢印はふつうの Ctrl+矢印として扱われた |
| Vial のキーで調整（下の表）。値は RAM だけで、電源を切ると既定に戻る | 好みが分かれる | — |

### 3 本指スワイプ

- 3 本指を同時に置いて一方向に動かすと、1 回のタッチにつき 1 回、その方向のキーを送ります。3 本指タップ（中クリック）はそのままです。
- 送るキーは Vial で変えられます。Vial の一番下の仮想キーの列（Mouse 1〜Mouse Wheel Right の 7 個）の後ろの 4 個が、左から **上・下・左・右** のスワイプです。
- 新しく書き込んだときの既定は Mac 向けです: 上 ⌃↑（Mission Control）・下 ⌃↓（アプリケーション Exposé）・左 ⌃→・右 ⌃←（Mac のトラックパッドと同じく、左へスワイプすると右の操作スペースへ）。
- **Windows では自分で割り当ててください**。既定の Ctrl+矢印は、Windows ではふつうの Ctrl+矢印として扱われます（確認済み）。割り当ての例（Windows では試していません）: Windows のタッチパッドに合わせるなら、上 Win+Tab（タスクビュー）・下 Win+D（デスクトップの表示）。仮想デスクトップの切り替えなら、左 Ctrl+Win+→・右 Ctrl+Win+←。
- 修飾キー付きのキーは、Vial の Quantum タブの「LCtl (kc)」などを置き、内側の枠をクリックして Basic タブのキーを選びます。
- **すでに Vial 入りの版を使っていた場合**、保存されたキーマップが残るので、この 4 個は空のままです。Vial で割り当ててください。
- レイヤー 6 の左のつまみの押し込みで、3 本指を **スワイプ ↔ ドラッグ** に切り替えます（LED が 1 回＝スワイプ・2 回＝ドラッグ）。3 本指ドラッグは、3 本で動かすと左ボタンを押したままカーソルが動き、指を全部離すと離します。

### 調整キー（Vial の User タブ）

| キー | 動き | LED（オレンジ）の点滅 |
| --- | --- | --- |
| Pad Spd- / Spd+ | カーソルの速さ（1/4〜8/4・既定 4/4） | 段数 |
| Pad Scr- / Scr+ | スクロールの速さ（既定は配布版と同じ） | 段数 |
| Pad Tap- / Tap+ | 1 本指タップの時間（150〜400 ms・既定 250 ms） | 段数 |
| Pad Drag | タップドラッグ 入/切 | 2 回＝入・1 回＝切 |
| Pad 3F D/S | 3 本指 ドラッグ/スワイプ | 2 回＝ドラッグ・1 回＝スワイプ |
| Pad Filt | チップの平滑化 80/40/20/10（小さいほど強い・既定 40） | 1〜4 回 |
| Pad Lift | 離すときに捨てる量 なし/3/5 フレーム（既定 3） | 1〜3 回 |
| Pad Reset | 全部を既定に戻す | 1 回 |

## まだ残っている問題

- ホストを切り替えた直後、もう一方の登録済みホストが先につないできて、数秒間入力が届かないことがある（RMK 本体の動き）。
- Dial は配布版と同じ 1 クリック 18°。Windows のスクロールは、ゆっくり 1 クリックずつ回すと反応しない（音量は 1 クリック 24° にした試作で同じく反応しなかった。原因は未確認）。
- Dial のスクロールの向きは、Windows の「設定 → Bluetooth とデバイス → マウス → スクロール方向」で、ホイールと一緒に変わる（音量は変わらない）。

## できること

Cornix左右をBLEでMadulaへ接続し、MadulaからPCへ入力を送ります。
本体の3キーと交換式入力モジュールを、同じキーマップで使えます。

- **53キー・5レイヤー** — Cornixの50キーとMadulaの3キー。Fn / Numなどのレイヤー操作に対応。
- **左右エンコーダー** — 上下スクロールを手元で操作。
- **選べるポインティング** — LPPS、PMW3610トラックボール、IQS9151タッチパッド。
- **状態を知らせるLED** — 接続状態、レイヤー番号の点滅、対応電池構成での残量目安。
- **USB CDC** — 各基板のログ取得と1200 baudリセットによるブートローダー移行。

RMK 0.9.0を使用し、依存関係は`Cargo.lock`で固定しています。
USB/BLEホスト接続に対応する構成ですが、BLEホスト接続を含む全条件での検証完了を示すものではありません。

## 入力モジュール

| モジュール | 操作 | 配布状況 |
| --- | --- | --- |
| LPPS | 自由なXYカーソル移動。平滑化・デッドゾーン付き | リリースUF2あり |
| PMW3610 / TB | トラックボールによるカーソル移動 | リリースUF2あり |
| IQS9151 | カーソル、1/2/3本指タップ、2本指スクロール | v0.1.0-rc.3から配布対象 |

IQSのタップは順に左・右・中央クリック。2本指移動は縦横スクロールです。
ピンチ、タップドラッグ、慣性スクロールは対応していません。

**モジュール交換は電源を切ってから行い、対応するMadulaファームウェアを使用してください。**
LPPSは起動時に中立位置を校正するため、起動直後は触れずに待ってください。

## はじめに

### 1. ファームウェアを選ぶ

[GitHub Releases](https://github.com/te9no/rmk-keyboard-madula/releases)から、Cornix左右と使用するMadulaモジュールの**計3ファイル**を取得します。

| ファイル | 書き込み先 |
| --- | --- |
| `cornix-left.uf2` | Cornix左 |
| `cornix-right.uf2` | Cornix右 |
| `madula-lpps.uf2` | LPPSを装着したMadula |
| `madula-tb.uf2` | PMW3610を装着したMadula |
| `madula-iqs.uf2` | IQS9151を装着したMadula（rc.3以降） |

3台とも同じリリースのRMKファームウェアに揃えてください。ZMKの左右ファームウェアとは接続できません。
`v0.1.0-rc.*`はプレリリースです。rc.1にはIQS版が含まれません。
rc.2は配布設定の修正により公開を取り止めたビルドです。
ELFはデバッグ用、JSONはビルド情報、`SHA256SUMS`は整合性確認用です。

### 2. 移行の準備

> **通常のZMK更新とは異なります。**
> RMK版は0x1000から配置され、旧SoftDevice領域を上書きします。
> ZMKへ戻すにはSoftDeviceの復旧が必要になる場合があり、アプリUF2のバックアップだけでは十分ではありません。
> 設定・ペアリング情報にも影響するため、対応基板・ブートローダー・復旧手段を確認してから移行してください。

[配布時の注意事項](docs/release-notes.md)を確認し、現在のファームウェアと必要な復旧データを保存してください。
異なる基板向けのファームウェアは流用しないでください。

### 3. 書き込む

移行準備ができたら対象基板をUF2ブートローダーで起動し、対応するUF2をそのドライブへコピーします。
再起動後、MadulaとCornix左右を起動してキー入力を確認してください。
RMK版導入後は各基板のCDCから1200 baudリセットも利用できます。

Windows用の[`flash-xiao.ps1`](scripts/flash-xiao.ps1)はMadulaのXIAO向け補助スクリプトです。
対象COMのPNP ID、UF2、ブートローダーを検査し、`CURRENT.UF2`を退避してからコピーします。
**Cornixには使用しないでください。** 引数はスクリプトを参照し、`-WhatIf`で対象を確認できます。

## キーマップとLED

### Cornixのエンコーダ

左の回転はスクロール、右の回転はWindows Radial Controller（Surface Dial互換）です。
右の押し込みはDialボタンになり、長押しでWindowsのメニュー、短押しで選択を操作します。
全レイヤーで共通です。回転は1ノッチ18度を初期値としています。
USBとPCへのBLE接続の両方で実機動作を確認しています。
BLEのHID定義が変わるため、更新後にPC側で登録を削除して再ペアリングが必要になる場合があります。
Windowsのメニュー表示状態はファームから取得できません。
保存形式の互換IDを固定し、通常の再ビルドによるペアリング情報の初期化を防いでいます。
旧ファームで既に鍵が失われた場合は、更新後に一度再ペアリングしてください。

HID実装は[sekigon-gonnoc/zmk-driver-hires-dial](https://github.com/sekigon-gonnoc/zmk-driver-hires-dial)
を参考にしています。RMK 0.9.0はリポジトリ内の `vendor/rmk` に固定し、
DialのUSB/BLEレポートと送信経路を追加しています。

[`keyboard.toml`](keyboard.toml)でキー割り当てを管理します。
CornixのMadula用キーマップを基準に、base / func / num / bt / naviの5レイヤーを保持しています。
変更後は再ビルドが必要です。

- **DYA Studio・Vialによる編集は非対応**です。
- ZMKのLayoutShiftとBTプロファイル操作は未移植で、該当位置は無効にしています。
- naviへの到達キーは現在の標準割り当てにありません。

Madula本体の外付けLEDはUSB接続をシアン、BLEホスト接続を青、未接続を赤で短く表示します。
レイヤー変更時は番号に応じた白点滅を表示します（baseは点滅なし）。

Cornix左右の2連LEDはPWM＋EasyDMAで独立駆動します。
内側（pixel 0）はFn＝薄い青、Num＝紫、BT＝シアン、navi＝橙で、
そのレイヤーが有効な間点灯します。ホストからCaps Lock有効の通知を受けると白を優先します。
外側（pixel 1）はMadulaへの接続成立時に緑を1.5秒表示し、未接続中は3秒ごとに橙を短く表示します。
base・Caps Lock無効・接続正常時は消灯してLED電源を切ります。
こちらはPCとの接続ではなく、CornixとMadula間の接続表示です。
点灯・色の変更は約300ms、消灯は約600msで緩やかにフェードします。
Cornix側のLED対応には左右それぞれのファームウェア更新が必要です。

電池残量表示は、**NiMH 1本・1MΩ/470kΩ分圧の対応Bat基板**が対象です。
緑は50%超、橙は21～50%、赤は20%以下の目安です。
電圧からの推定であり、正確な残容量や充電状態を示すものではありません。
OSへのBLE残量通知は未対応です。

## USB CDCログ

調べたい基板をUSBで接続し、シリアルモニターを**115200 baud / 8N1 / フロー制御なし / DTR有効**で開きます。
各基板のログは個別に取得します。左右のログをMadulaへ集約する機能はありません。

1200 baudでDTRを500 ms以上有効にしてから落とすと、ブートローダーへ移行します。
通常の115200 baudでの開閉ではリセットしません。
入力イベントが含まれる場合があるため、パスワード入力中の収集や未確認のままの公開は避けてください。
起動初期・クラッシュ直前・バッファ容量を超えたログは取得できない場合があります。

## ソースからビルド

Rust 1.94.1、ARM GCC、libclangを用意します。

```sh
rustup toolchain install 1.94.1 --profile minimal --target thumbv7em-none-eabihf
python3 -m unittest discover -s tests

# Cornix左右
cargo +1.94.1 build --release --locked --bin cornix-left --bin cornix-right

# Madula：装着モジュールに合わせて1つ選択
cargo +1.94.1 build --release --locked --bin madula-central --features lpps,battery-audit
cargo +1.94.1 build --release --locked --bin madula-central --features pmw3610,battery-audit
cargo +1.94.1 build --release --locked --bin madula-central --features iqs9151,battery-audit
```

`lpps` / `pmw3610` / `iqs9151`は同時に有効化できません。
`battery-audit`は対応回路の電圧監視・残量推定を有効にする機能名です。
ELFは`target/thumbv7em-none-eabihf/release/`に生成されます。
UF2を含む配布用パッケージは[`build-release.sh`](scripts/build-release.sh)を参照してください（Cornix左右・LPPS・TB・IQS）。

Dockerでのビルドは[`build-docker.sh`](scripts/build-docker.sh)、GitHub Actionsでのビルドは
[`Firmware release`](.github/workflows/release.yml)を利用できます。
タグから作成されるリリースは下書き・プレリリースで、公開操作は別途必要です。
